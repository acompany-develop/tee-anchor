# Threat Model

## 想定する攻撃者

### 攻撃者の能力

- 自身が物理的にアクセス可能な TEE 対応マシンを所有する
- そのマシンに対し、Battering RAM、TEE.fail 等の**物理攻撃を実行できる**
- ただし、攻撃者は**ターゲット組織が管理するマシンには物理アクセスできない**
- ネットワーク上の通常の能力（公開 PKI への観測、通信傍受等）は持つ

### 攻撃者の目標

ターゲット組織が管理する TEE 上で動作している（とリレーパーティが信じる）ワークロードに対し、**実際には攻撃者が物理アクセス可能なマシン上**でそのワークロードを動作させ、その結果を組織管理下マシンの結果と偽る。

これによって：

- 機密データの不正取得
- 計算結果の改ざん
- TEE が提供する完全性保証の無効化

を達成する。

## 想定する Proxy/Relay 攻撃のシナリオ

1. 攻撃者は手元の物理攻撃可能マシン上で CVM/Enclave を起動し、正規の TEE Attestation Quote を取得する
2. 攻撃者は別途、ターゲット組織が発行している組織エンドースメント証明書（公開情報）を取得する
3. 攻撃者は両者を組み合わせて Verifier に提示する
4. Naive な検証では「TEE Attestation OK」「組織エンドースメント証明書 OK」として通過してしまう

これを**Proxy 攻撃**と呼ぶ。

## TEE Anchor の防御策

Quote/AR に含まれるチップ固有識別子（PPID/CHIP_ID）と、組織エンドースメント証明書の Critical Extension に記録された Chip ID を **bit-for-bit 照合**する。

これにより：

- 攻撃者の手元マシンの Chip ID と、組織が発行した証明書中の Chip ID が一致しないため、検証失敗
- Chip ID はハードウェアで固定であり、ソフトウェア的に書き換え不可能
- TEE Attestation 自体が Chip ID を含む形でハードウェア署名されているため、Chip ID の偽造は PCK/VCEK 秘密鍵を抽出しない限り不可能

## 防げない攻撃（Out of Scope）

### BORE（Break Once, Run Everywhere）攻撃

- 攻撃者が**組織管理下の正規マシン 1 台**を物理的に手に入れ、PCK/VCEK 秘密鍵を抽出した場合
- その鍵で任意の偽 Quote を生成できる
- 対応する組織エンドースメント証明書も既に存在するため、Chip ID 照合も通る

→ **本研究の対応**: 組織は自身が管理する各マシンの物理セキュリティに責任を負う、と前提する。組織管理下マシンへの物理アクセス事象は検知・対応されることを仮定する。攻撃者は組織外部の人間に限定する。

### Side-Channel 攻撃（メモリプロビング、電磁波解析等の能動的物理攻撃）

- 組織管理下マシン内のメモリを動作中に物理プロビングする攻撃
- これは BORE と同種の前提逸脱として扱う

### TEE 内ソフトウェアの脆弱性

- Enclave/CVM 内で動作するアプリケーション自体の脆弱性
- これは TEE 一般の課題であり、本研究の解決対象ではない

### Denial of Service

- 組織 CA の可用性攻撃
- 組織エンドースメント証明書の不発行
- これらは可用性の問題で、本研究はあくまで完全性（authenticity）に焦点

## 前提

- 組織 Root CA の秘密鍵は安全に管理される（HSM、Cold Storage 等）
- 組織は管理下マシンを物理的に保護できる
- Intel/AMD の PCK/VCEK 発行インフラ自体は健全である
- Verifier 側のホスト OS と検証バイナリは健全に動作する（TEE Anchor 自体の自己防御は対象外）
